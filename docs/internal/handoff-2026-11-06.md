## Rules

- Any visitor works. Nothing hardcoded: no fixed amounts, receivers or deploy-time allowlists. Safety comes from each visitor's own `/setup` row caps.
- Every shop uses the approved Ferry tray (`docs/internal/design/approved-tray-ferry.jpg`): tabs on top, an icon flow card, labelled fields with space between them, one gold CTA, short clean status lines. Test in the city, not the legacy standalone pages.
- The gold CTA and the in-shop NEAR AI agent must both make real mainnet transactions under the session, with no wallet popup after setup.
- Zero NEAR wasted. Prefer in-place upgrades. Tear down unused contracts to `nearcarta.near` and reuse the NEAR. Every contract needs a teardown path.
- Mainnet deploy, close, reap, upgrade and funding transactions are not run from Cursor chats. Chats write code, scripts and dry runs only. Keys never appear in chat, logs or commits.
- Small real commits, normal merges, never force-push. Gitleaks must report no leaks before a merge. Merge only when every check name has a green run.
- Public files never name the owner, other projects or competitors.
- Update the local action log after every action. README proofs are added only after a verified city test.
- Shop chats run on `deepseek-v41-flash-1017` with high reasoning and queued messages. Never message a chat mid-run.

## The shop loop

When a shop chat finishes:

1. Merge its PR when every check name has a green run and gitleaks reports no leaks.
2. Deploy.
3. Test in the city like a judge: deep, any user, the approved tray, and both the gold CTA and the AI making real transactions.
4. Send failures back to the same chat with screenshots and transaction evidence. Repeat until the shop is complete.

Before testing, attack the idea as a judge would: the real user problem, who gets paid and why, what is new against the ecosystem, and why these judges would care.

## Design standard

The reference is `docs/internal/design/approved-tray-ferry.jpg`, the city Ferry tray.

The tray, from top to bottom:

1. Three tabs.
2. An icon flow card with real token and chain icons, never a placeholder square.
3. Labelled fields, label above and field below, with space between them.
4. One clear gold CTA.
5. At most two short status lines, with a human-labelled transaction link when there is one.

The design check for every shop pull request:

- The shop's own chat opens https://nearcarta.vercel.app in its browser, enters the shop through All shops inside the city (not the legacy standalone page), and screenshots every tab at 1280x800 and 390x844. The screenshots go in the pull request with the commit recorded.
- Fail on: stacked unlabelled white text, any button under 40 px or tap target under 44x44, more than one gold CTA, no icon flow card or a placeholder icon, more than two status lines, overlap with All shops, Back to town or the AI bubble, or a "something did not load" error.
- The legacy `/design/D8_shops/?shop=<id>` page renders the same tray.

## Mainnet work is the coordinator's

Chats never send a mainnet transaction. The coordinator runs the deploy scripts after a green merge. Each run is dry first, then live, and only while the balance covers the stake plus a gas cushion. Close or reap first, check the balance, then create. Never run two creates in flight.
